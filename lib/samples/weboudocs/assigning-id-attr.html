Assigning IDs to Output Elements

Purpose

The htmlIdAttr mode assigns an id attribute to the resulting HTML element. This mode is typically invoked as part of htmlAttrs processing and ensures each output element receives a meaningful and stable identifier, when applicable.

Placement

This functionality is implemented in the following stylesheet:

common/publish/matter/htmlattrs.xsl

Features

The htmlIdAttr mode supports the following strategies for assigning the ID:

  • Passing a direct value using the directId parameter
  • Extracting a value from a parsable outputclass string
  • Copying the original id attribute from the source DITA element

Synopsis

Mode: htmlIdAttr.

Parameter Type Meaning
directId xs:string Overrides all other sources and assigns this value as the output ID

Usage

In most cases, this mode is applied automatically within the htmlAttrs template. However, you can also invoke it explicitly in custom templates.

Example: Passing a direct ID

<xsl:apply-templates select="." mode="htmlIdAttr">
    <xsl:with-param name="directId" select="loc:assembleMyCustomId(.)"/>
</xsl:apply-templates>

Example: Parsing from outputclass

<note outputclass="id='deadlyDanger' class='critical_signal'">...</note>

Example: Copying from preprocessed source

<note id="d2486e220">...</note>
Important
DITA Open Toolkit preprocessor replaces original id values with generated. For example, an element receives a string like d2486e220 as a value of the id attribute, while you assigned another value, for example myBestMiteId, in the source.

Assignment Priority

The htmlIdAttr mode applies the following priority when choosing which id to assign:

  1. If a directId parameter is passed, it is always used.
  2. Else, if outputclass contains a parsable id value, that value is used.
  3. Else, if the source element has an id attribute, it is copied.
  4. Else, no id is added to the output element.
Note
There is usually no need to call this template directly, since htmlAttrs applies it by default.

Modifying Default Behavior

To override the default behavior, define a new template with the htmlIdAttr mode in your customization, targeting specific element types as needed.
