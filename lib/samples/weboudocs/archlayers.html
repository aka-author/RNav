Plug-in Structure and Layer Responsibilities

Architectural Layers

The architecture of the plug-in consists of two primary layers:

  • The plug-in itself
  • Layouts embedded within the plug-in
  • Customizations

Each layer is responsible for specific stages in the transformation process and for producing distinct parts of the output document.

Responsibilities of the Plug-in

The plug-in acts as the main control layer. It performs preprocessing and postprocessing operations required to prepare and finalize output documents. Its responsibilities include:

  • Linking the top-level ditamap, submaps, and topic files into a single internal structure
  • Filtering the content according to applicable conditions
  • Arranging image files referenced from the source topics
  • Copying CSS files, JavaScript libraries, and other predefined technical assets to the output folder
  • Providing localization files that define UI strings and labels used in the output

Responsibilities of Layouts

Layouts are modular components embedded in the plug-in. Each layout is responsible for generating the actual output documents and defining their structure, visual layout, and behavior. A layout handles the following tasks:

  • Generating output HTML files from the internal structure
  • Generating additional files, such as:
    • Table of contents in JavaScript format
    • Search index files in JavaScript format
  • Providing its own:
    • CSS files
    • JavaScript libraries
    • Icon files
  • Optionally replacing or extending the localization files provided by the plug-in

Base Layouts

The plug-in includes a set of predefined base layouts. Each base layout defines the structure, layout, and behavior for a specific category of output documents. Examples of base layouts include:

  • The classtatic layout, used for classical static web help systems
  • The rawdump layout, used for generating one-pager draft documents

Each base layout defines:

  • The general structure of the output files
  • The default visual representation
  • The default behavior of the documents

Layout Versions

Each layout can evolve through a sequence of versions. New versions of layouts are added as the plug-in is updated, while existing versions remain available. This versioning model ensures compatibility and supports long-term maintenance. Layout versions are cumulative and non-destructive.

Customizations

Users can tailor output documents by creating customizations. A customization is a lightweight extension of a base layout. It allows users to redefine specific aspects of:

  • Document structure
  • Visual layout
  • Interactive behavior

Multiple customizations can be created for each base layout, enabling targeted adaptation for different publishing needs without altering the original layout.
