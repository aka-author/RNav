Understanding Build Properties

Why Use Properties with DITA OT

Property files allow you to configure and customize the behavior of the DITA Open Toolkit (DITA OT) without modifying the build scripts directly. This approach is widely used in the Java stack, particularly with tools like Apache Ant, which underlies DITA OT. Properties enable the reuse of common settings across projects and help maintain cleaner and more manageable configurations.

What Is a Property

A build property is a pair consisting of a property name and a property value. DITA OT collects all defined properties and passes them to plug-ins during output generation. Plug-ins use these properties to adjust the formatting, location of output files, paths to resources, and other runtime behaviors.

Properties File Format

Build properties are defined in plain text files. Each property must appear on a separate line. Line breaks within values are not allowed. The standard file type is .properties.

Rules for a Property Definition

The basic syntax for defining a property is:

property_name=property value

Rules for Property Names

  • Must not contain whitespace or the equals sign
  • May include letters, digits, periods, and underscores
  • Must be unique within the same file

Rules for Property Values

  • Any printable characters are allowed
  • Leading and trailing spaces are preserved
  • Backslashes are used for escaping and must be doubled when used as characters, for example in Windows file paths

Example

customization.dir=C:\\writing\\tools\\customizations\\corporate-layout
dita.temp.dir=c:\\tmp\\!ditatoo_weboutput_tmp
clean.temp=no
